# @tennis-buddy-finder/backend

Convex backend for **Tennis Buddy Finder** (find tennis partners in Portugal). All server code lives in
`convex/`. The Nuxt 4 app in `apps/web` (via `convex-nuxt` / `convex-vue`) imports this package to get the
generated `api` object, so every public function here is the app's API surface.

The `convex` Claude plugin is installed. Use the `convex-expert` agent for non-trivial Convex work
(schema design, indexes, actions, auth wiring, components) and run `convex-reviewer` before finishing
backend changes. The plugin's lint hook blocks `.filter()` on db queries and legacy positional function
syntax; its stop hook runs codegen + `tsc` when `convex/*.ts` changed.

## Layout

```
convex/
  schema.ts          # single source of truth for tables + indexes
  convex.config.ts   # defineApp(); register components here (app.use(...))
  healthCheck.ts     # trivial public query
  model/validators.ts # shared literal unions (statuses, enums) + paginated() return helper
  _generated/        # codegen output. NEVER hand-edit. Regenerated by `convex dev`.
```

One file per domain/table: `convex/users.ts`, `convex/availability.ts`, `convex/matches.ts`, etc.
Shared helpers that are not registered functions go in `convex/model/` (e.g. `convex/model/auth.ts`).
`crons.ts` for recurring jobs, `http.ts` for HTTP routes (`httpAction` handlers), `auth.config.ts` for auth.

## Function conventions (Convex 1.45+)

- **Object form only, with `args` AND `returns` validators on every function**, public or internal.
  Use `returns: v.null()` for void handlers. Validators are runtime guards, not type hints.
- Imports: `query|mutation|action|internalQuery|internalMutation|internalAction|httpAction` from
  `./_generated/server`; `api|internal` from `./_generated/api`; `v` from `convex/values`;
  `Doc`/`Id` types from `./_generated/dataModel`.
- **Default to internal.** `query`/`mutation`/`action` only for things `apps/web` calls directly.
  Scheduled callbacks, helpers, and admin ops are `internal*`.
- `ctx.runQuery` / `ctx.runMutation` / `ctx.runAction` and `ctx.scheduler.runAfter` take function
  references (`internal.users.get`), never strings or raw imports. Do not call `runQuery`/`runMutation`
  from inside a `query`; extract a plain helper instead.
- Actions have no `ctx.db`. External calls (email, geocoding, LLMs) go in actions; persist results via
  `ctx.runMutation(internal.x.y, ...)`. `"use node";` only at the top of files that need Node builtins,
  and such files may export actions only. Prefer Web Crypto over `import crypto`.
- `ctx.db.get("table", id)`, `ctx.db.patch("table", id, {...})`, `ctx.db.delete("table", id)` (table-name
  first).
- `v.id("table")` for ids (never `v.string()`), `v.union(v.literal(...))` for enums, `v.optional()` for
  optional fields, `null` not `undefined`. Bound every client-supplied number (`limit`, deltas, ranges).
- No `Date.now()` in queries (breaks reactivity); pass `now` as an arg or use status fields. Mutations may.
- No JS reserved words as export names (`delete` -> `remove`).

```ts
export const listByDistrict = query({
  args: { district: v.string(), paginationOpts: paginationOptsValidator },
  returns: v.object({ page: v.array(v.any()), isDone: v.boolean(), continueCursor: v.string() }),
  handler: async (ctx, args) =>
    ctx.db.query("users").withIndex("by_district", (q) => q.eq("district", args.district))
      .order("desc").paginate(args.paginationOpts),
});
```

## Schema and queries

- Every read path gets an index in `schema.ts`; query with `.withIndex(...)`, never `.filter(...)`.
  Index names list the columns in order: `.index("by_district_and_skillLevel", ["district", "skillLevel"])`.
  Never include `_creationTime` in an index (added automatically) and never prefix table/index names with `_`.
- Range builder supports only `eq/gt/gte/lt/lte` chained on the callback param. There is no `.range()`,
  `.count()`, or `.skip()`. Builder terminals: `collect | take | first | unique | paginate`.
- Never unbounded `.collect()` on a table that grows. Use `.paginate(paginationOpts)`
  (`paginationOptsValidator` from `convex/server`) or `.take(n)`.
- Adding a field to a populated table: add as `v.optional()`, backfill, then tighten. A failed schema push
  blocks all function deploys.
- Full-text/vector search: `.searchIndex(...)` / `.vectorIndex(...)` on the table, not an external service.

## Auth

- Any protected function: `const identity = await ctx.auth.getUserIdentity(); if (!identity) throw ...`.
  Identity comes from `ctx.auth`, never from a `userId` arg.
- The `users` table is keyed by `authId` (the auth provider's user id, i.e. `identity.subject`) with
  `.index("by_authId", ["authId"])`. Resolve the caller through a shared helper in `convex/model/auth.ts`:

```ts
export async function getCurrentUser(ctx: QueryCtx | MutationCtx) {
  const identity = await ctx.auth.getUserIdentity();
  if (!identity) throw new Error("Not authenticated");
  const user = await ctx.db.query("users")
    .withIndex("by_authId", (q) => q.eq("authId", identity.subject)).unique();
  if (!user || user.bannedAt !== undefined) throw new Error("Not authenticated");
  return user;
}
```

- Mutations/queries that take an `_id` (`cancelMatch`, `updateAvailability`) must load the doc and compare
  its owner field to `user._id` (compare against `users._id`, not `identity.subject`, when the schema
  stores `v.id("users")`). Writes with a foreign-key arg check ownership/membership of the parent too.
- Auth is not wired until `convex/auth.config.ts` exists; without it `getUserIdentity()` is always `null`.
  Do not add auth checks to public functions until the provider + `users` table exist; make privileged
  functions `internal*` instead.

## Data modeling for this project

- Timestamps are `v.number()` epoch ms (`createdAt`, `startsAt`, `expiresAt`). Never ISO strings.
  The one deliberate exception is `profiles.birthDate`, a calendar date stored as `YYYY-MM-DD` so age
  checks do not drift with timezones.
- Location is structured: `district: v.string()`, `municipality: v.string()`, optional `lat`/`lng` numbers.
  Index on `["district"]` and `["district", "municipality"]` for browse/search paths.
- Enums via literals: `skillLevel: v.union(v.literal("beginner"), v.literal("intermediate"), ...)`,
  `matchStatus: v.union(v.literal("pending"), v.literal("accepted"), ...)`.
- Flat documents; relate via `v.id("table")` + index. No nested arrays of objects that need querying
  (availability slots, match requests, messages are their own tables). Small bounded arrays only
  (e.g. `preferredSurfaces`).
- Files (avatars): store `Id<"_storage">` (`v.id("_storage")`), resolve with `ctx.storage.getUrl()` on
  read; upload via `ctx.storage.generateUploadUrl()` in a mutation.
- Recurring work in `crons.ts` (`cronJobs()`, targets `internal.*`); one-off delays via
  `ctx.scheduler.runAfter(ms, internal.x.y, args)` from a mutation.
